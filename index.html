About

I'm a Product Manager on o9 Solutions' AI R&D team. My work spans the full stack of making AI a first-class citizen of enterprise software: a knowledge graph that gives agents real platform context, an agentic engine that builds and extends configuration on top of it, the UI that makes that usable, and the analytics that close the loop.

Most of my current work sits underneath the products people see: a knowledge graph that gives agents a real model of the platform, an agentic configuration engine that can build and extend planning solutions on top of it, and the tooling that turns both into usable products for implementers and customers.

Before moving into product, I spent three years in delivery at o9, implementing large-scale supply chain planning solutions for Fortune 500 retailers — most notably leading the replenishment planning build for Starbucks. That hands-on delivery experience — watching where configuration got slow, fragile, and expert-bound — is a lot of what shapes the AI R&D products I build today.

I hold a B.Tech in Electrical and Electronics Engineering from NIT Karnataka, Surathkal.

01

Config Graph (EKG)

Knowledge Graph · Agent Infrastructure

Problem

AI agents need to disambiguate and reason about platform entities — measures, attributes, views, plugins, dimensions, reports — but there was no rich, machine -readable map of what exists on a tenant or how it connects.

Approach

Built a knowledge graph over o9's configuration and fixed pipeline — every measure, attribute, dimension, view, plugin, and button modeled as a node with rich descriptive context, navigable by agents to identify and disambiguate platform entities.

Impact

Now the foundational context layer for Agent Builder and Skill Builder — any agent can be scoped with real platform context instead of hardcoded knowledge. Other AI R&D products, including Config Model Extension and Synthetic Data Generation, are built directly on top of it.

  • Knowledge Graph
  • Agent Builder
  • Skill Builder
  • Platform Context
02

Config Model Extension

Agentic Configuration · MCP Tooling

Problem

Configuration was the friction point blocking agentic delivery: high interaction cost, tribal knowledge requirements, and fragile manual dependency ordering — turning a 4–6 month implementation into a slow, expert-bound slog.

Approach

Shipped first-class CRUD tools for every config entity over Nova's MCP interface, with two flows on the same engine — an Express Lane for precise, spec-driven builds, and an Architect Lane where agents explore the Config Graph, propose a plan grounded in o9's Reference Model graph DB, and execute end-to-end after review.

Impact

Implementations that used to take 4–6 months can now ship in weeks, sometimes days — for both greenfield provisioning and extending existing solutions (e.g. stat forecasting → ML-based forecasting) — with continuous improvement built in as a byproduct.

  • Agent-Driven Config
  • MCP Tools
  • Reference Models
  • Greenfield Provisioning
03

Config Designer UI

Agentic UI · Solution Architect Agent

Problem

The legacy configuration UI was slow and click-heavy, with no visual way to understand how a tenant was actually configured before changing it.

Approach

Designed an agentic configuration UI powered by the Solution Architect agent (built as part of Config Model Extension) — giving users a guided, visual way to build and understand configuration instead of clicking through disconnected screens.

Impact

Replaced a workflow implementers actively avoided with one that's fast, transparent, and self-explanatory — turning configuration from a black box into something users can actually see and reason about.

  • Agentic UI
  • Solution Architect Agent
  • Config Visualization
